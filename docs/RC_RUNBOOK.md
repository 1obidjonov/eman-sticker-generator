# Runbook Windows Release Candidate

Этот документ описывает выпуск Eman Sticker Generator `0.8.0-rc.4`.
Release Candidate предназначен для внутреннего пилота и становится публичным
только после успешной цифровой подписи.

## Критерии готовности

Кандидат считается собранным, если Windows workflow подтвердил:

1. Git-тег совпадает с версией `package.json` и указывает на проверяемый commit.
2. Production-аудит, сборка, тесты и демонстрационные экспорты прошли.
3. NSIS-установщик имеет ожидаемое имя, размер и PE-заголовок.
4. Распакованное приложение прошло runtime smoke-тест.
5. Установщик отработал в тихом режиме и создал оба ярлыка.
6. Установленное приложение дважды прошло smoke-тест.
7. Настройки сохранились после перезапуска и после удаления приложения.
8. Установщик и все отчёты совпадают с SHA-256 манифеста.

Для публичной публикации дополнительно обязателен Authenticode-статус `Valid`.

## Подготовка репозитория

Проект должен находиться в приватном или публичном GitHub-репозитории с
включёнными GitHub Actions. Рабочая ветка перед тегом должна пройти workflow
`Quality`.

Если используется сертификат подписи, добавьте Actions Secrets:

- `WINDOWS_CSC_LINK`;
- `WINDOWS_CSC_KEY_PASSWORD`.

Сертификат и пароль нельзя сохранять в Git, документации или release-архиве.

## Создание внутреннего RC

Из чистой основной ветки:

```bash
git tag -a v0.8.0-rc.4 -m "Eman Sticker Generator 0.8.0-rc.4"
git push origin v0.8.0-rc.4
```

Push тега запускает сборку и сохраняет workflow artifact, но сам по себе не
публикует GitHub Release. Это позволяет проверить неподписанный внутренний
кандидат без случайной публичной раздачи.

Альтернативный автоматизированный способ после зелёного workflow `Quality`:

```bash
git branch release/v0.8.0-rc.4
git push origin release/v0.8.0-rc.4
```

Workflow `Release Candidate Request` проверяет, что имя ветки совпадает с
версией приложения и что ветка указывает на актуальный `main`. Затем он создаёт
аннотированный тег и запускает Windows RC validation с отключённой публикацией.

## Проверка результатов

Скачайте artifact `eman-sticker-generator-v0.8.0-rc.4-windows-x64` и проверьте:

| Файл | Ожидаемый результат |
|---|---|
| `release-verification.json` | `status: passed` |
| `windows-smoke-report.json` | `status: passed`, `packaged: true` |
| `windows-lifecycle-report.json` | `status: passed`, два smoke-запуска |
| `release-manifest.json` | версия и состав совпадают с RC |
| `checksums.sha256` | все SHA-256 совпадают |
| `sbom.cdx.json` | CycloneDX production SBOM |

Неподписанный кандидат разрешено передавать только заранее определённой
внутренней группе тестирования.

## Публикация подписанного prerelease

После проверки внутреннего artifact запустите workflow вручную:

- `release_tag`: `v0.8.0-rc.4`;
- `publish_release`: `true`.

Workflow повторно собирает кандидат из commit тега. Публикация блокируется,
если Authenticode-подпись отсутствует или имеет статус, отличный от `Valid`.
Версия с суффиксом `-rc.*` публикуется как GitHub prerelease.

## Решение go / no-go

RC допускается к пилоту, если:

- автоматические отчёты имеют статус `passed`;
- нет блокеров установки, запуска, сохранения данных и экспорта;
- назначены тестировщики и ответственный за сбор обратной связи;
- SHA-256 установщика зафиксирован в карточке пилота.

При ошибке не заменяйте байты существующего тега. Исправьте дефект, увеличьте
номер кандидата и выпустите новый тег.
