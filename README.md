# Eman Sticker Generator — Stage 8 RC

Рабочее desktop-приложение для создания шаблонов товарных наклеек. Фон,
экспортированный из Figma, хранится без изменений, а динамические текстовые и
QR-поля размещаются отдельным слоем.

## Реализовано

### Core

- модели `Template`, `Field`, `IBackgroundAsset`, `Product`;
- валидация шаблонов;
- `composeSticker()` с независимыми слоями background/fields;
- text-fit в порядке shrink → wrap → ellipsis;
- браузерное и Playwright/Chromium-измерение текста;
- QR-рендер;
- поддержка SVG, PNG и JPG-фонов.

### Electron

- безопасное окно: `contextIsolation: true`, `sandbox: true`,
  `nodeIntegration: false`;
- типизированный IPC через изолированный CommonJS preload;
- хранение каждого шаблона в отдельной папке;
- создание, открытие, сохранение, переименование и удаление шаблонов;
- атомарная запись `template.json`;
- проверка путей и защита неизменяемых метаданных фона;
- превью шаблонов в менеджере.

### React + Konva

- экран менеджера шаблонов;
- загрузка SVG/PNG/JPG-фона;
- добавление текстовых и QR-полей;
- выбор, drag, resize и привязка координат;
- масштабирование и сетка;
- панель свойств текстовых и QR-полей;
- удаление полей;
- `Ctrl/Cmd + S`, `Delete`, `Esc`;
- точный live-превью через тот же `composeSticker()`, который будет
  использовать экспорт.

### Экспорт

- `ExportEngine`, не зависящий от Electron и React;
- `IRasterizer` с реализацией на Sharp и точным масштабом 1×–3×;
- SVG без повторной сборки, PNG без потерь и JPG на белом фоне;
- настройка качества JPG;
- ZIP-упаковка при выборе нескольких форматов;
- единый SVG для предпросмотра и выходных файлов;
- base64-вложение QR, одинаково поддерживаемое Chromium и Sharp;
- системный диалог сохранения и безопасный IPC;
- отдельный экран экспорта с ручными данными тестового товара.

### Парсеры и массовая генерация

- plugin-контракт `IProductParser` и независимый `ParserRegistry`;
- первый рабочий плагин `SchemaOrgProductParser`;
- извлечение товара из JSON-LD Schema.org с fallback на OpenGraph,
  microdata и `h1`;
- защита от небезопасных схем, URL с credentials и локальных адресов;
- один лениво запускаемый Chromium-контекст на всю партию;
- ограниченный `PlaywrightBrowserPool`, общий для парсера и измерения текста;
- самостоятельный `RenderQueue` с настраиваемой конкурентностью;
- продолжение партии при ошибке отдельной ссылки;
- отмена задачи и push-прогресс через типизированный IPC;
- экран массовой генерации с вводом до 1000 ссылок;
- сетка готовых превью и отдельные карточки ошибок;
- пакетный ZIP всех готовых наклеек в SVG/PNG/JPG;
- уникальные и безопасные имена файлов внутри архива.

Новый parser-плагин добавляется отдельным классом и одной регистрацией в
`src/main/index.ts`; очередь, UI и генератор менять не требуется.

## Запуск приложения

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Для production-сборки:

```bash
npm run build
npm start
```

Для Windows-установщика:

```bash
npm run package:win
```

Подробности: [`docs/WINDOWS_RELEASE.md`](docs/WINDOWS_RELEASE.md).

Для локальной проверки release-метаданных:

```bash
npm run release:prepare
```

CI/CD: [`docs/CI_CD_RELEASE.md`](docs/CI_CD_RELEASE.md).

## Проверка

```bash
npm run check
npm run audit:prod
```

Проверки выполняют TypeScript typecheck, сборку Electron/preload/renderer,
автоматические тесты и два контрольных прохода:

- `template → composeSticker → SVG/PNG/JPG → ZIP`;
- `URL → Playwright parser → Product → queue → compose → batch ZIP`.

Контрольные файлы появятся в `examples/output/`.

## Структура данных

```text
<userData>/templates/<template-id>/
  template.json
  background.svg | background.png | background.jpg
  thumbnail.png

<userData>/settings.json
<userData>/logs/application.log
<userData>/logs/application.previous.log
```

SVG используется как статичный фон. Приложение читает только размеры корневого
`svg/viewBox`; содержимое, слои и path исходного файла не редактируются.
